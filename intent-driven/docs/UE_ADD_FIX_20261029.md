# 新增 UE 流程修复与实测

日期：2026-10-29。服务器：YOUR_SERVER_IP。

## 确认的问题

最近失败任务实际调用 `/api/ues/activate`，执行 `switch_ue`（切换主 UE 身份），不是 `/api/ues` 的 `add_ue`（新增独立 UE）。原“激活 UE”按钮还会隐式使用新增表单中的 IMSI，导致两种操作混淆。

- `208950000099001` 在签约表存在，但鉴权表不存在。原页面没有展示这个差异，切换身份时因此失败。
- `208950000000032` 的签约切片为 `222/000123`，当前 UPF 实际注册的是 `222/00007b`，因此不能直接建立该签约切片的会话。
- 在线 IMSI 不能同时用于另一个独立 UE；原页面缺少可用选择与直观说明。
- 后端即使复用完整订户，也无条件依赖模板订户，存在不必要的校验失败。

## 已部署改动

1. 页面显示每个订户的鉴权、签约与在线状态，补充仅有在线会话而缺签约的节点信息。
2. 提供“选择已就绪切片”下拉框，要求 UPF 注册及 CU/DU 三份广告配置均就绪。
3. 提供“填入未占用 IMSI”，已有离线订户可点击“用于新增”；在线订户禁用该操作。
4. 将“激活 UE”明确命名为“切换主 UE 身份”，不再隐式读取新增表单；切换前提示会话影响。
5. 新增接口预校验并返回明确 HTTP 400，后台执行时在操作锁内再次校验。
6. 新增时识别缺少鉴权的已有订户，提示自动补齐；不会因为仅补鉴权而重置未指定的 QoS。
7. 完整订户无需依赖克隆模板；模板只用于补齐缺失的表。

## 实际测试

| 场景 | 结果 |
|---|---|
| 全新 IMSI `208950000000132`，切片 `3/000003`，5QI 6、AMBR 37Mbps | 自动创建鉴权和签约，新增 UE4 获得 `12.1.1.5`，PDU 会话接受，用户面 ping 通过，QoS 回读一致 |
| 已有签约但缺少鉴权的 `208950000099001` | 自动补齐鉴权，新增 UE4 获得 `12.1.1.5`，会话及用户面通信通过 |
| 用在线主 UE IMSI 再新增 | HTTP 400，明确提示不能重复创建，无新任务 |
| 选择 UPF 未注册的 `1/000123` | HTTP 400，明确提示先激活切片，无新任务 |

两个正向测试均完成节点回滚，并将测试订户的数据库数据恢复到测试前状态。临时 IMSI 132 已从数据库及重建期望状态中删除；001 恢复测试前“有签约、无鉴权”的状态，之后通过新增流程仍可自动补齐。测试的私有鉴权快照仅留在服务器，未下载。

清理时发现新增 UE 的原有回滚语义会保留新建订户，因此另行按测试前快照恢复数据库及这两个测试 IMSI 的期望状态。`intent_state.json` 未保留逐字节等同性；主 UE 配置和节点配置期望文件与测试前哈希一致。

原有主 UE 097、UE2 031、UE3 095 均保持原节点和地址，用户面通信通过。最终 8 个关键服务正常，26 个容器运行，暂停的两个定时器已恢复 active。

原有后端回归 24 项、新增回归 3 项均通过；前端 JavaScript 逻辑测试 4 组通过，覆盖可用切片筛选、新 IMSI、QoS 参数、在线身份拦截及切换表单独立性。未进行浏览器点击和视觉验收。

## 使用方法

刷新 `http://YOUR_SERVER_IP:8099/`，在新增区域选择已就绪切片，点击“填入未占用 IMSI”，再点击“新增 UE 节点”。也可以点击离线订户旁的“用于新增”。切换已有主 UE 身份使用独立的“绑定 IMSI / 切换主 UE 身份”区域。
