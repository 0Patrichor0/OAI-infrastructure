# 端到端切片创建与验收

日期：2026-10-29。服务器：YOUR_SERVER_IP。

“新建切片”统一执行 `activate_slice`，同时配置核心网与 RAN，并通过 UE 实际建会话和通信验收。任何验收项失败都返回意图失败，不允许仅完成某一侧就标记成功。

## 成功条件

| 范围 | 必须通过的检查 |
|---|---|
| 核心网配置 | AMF 的 nssai、SMF 的 discovery/default DNN、本地 subscription/default DNN 都包含目标 SST/SD |
| 核心网运行态 | AMF/SMF 容器 healthy，实际挂载文件内容一致，进程启动晚于该配置修改 |
| RAN 配置 | CU-CP、CU-UP、DU 三份配置均包含同一个 SST/SD 配对 |
| RAN 运行态 | 三个服务 active，实际进程使用对应配置路径，并在配置修改后启动 |
| UPF | 配置包含目标切片，且 NRF discovery 返回的已注册 UPF profile 实际包含目标切片和 default DNN |
| 订户及 UE | 目标订户切片一致，UE 日志请求目标切片，重建会话成功，用户面 ping 通过 |

上述“RAN 生效”指 S-NSSAI 接入配置与实际通信，不代表已经实现 PRB、带宽或调度器资源隔离。

## 修复的问题

- 自然语言“新建切片”原先缺少核心网配置权限；现在该意图包含统一配置核心网与 RAN 的含义。明确的新建切片表达优先进入确定性解析，避免被当成仅修改订户业务档案。
- 核心网原先只查 YAML anchor，可能把“有定义、无 AMF/SMF 引用”误判为就绪。现在解析实际 YAML 引用并补齐缺失部分。
- RAN 原先分别查 SST 和 SD 是否出现在整个列表，可能把不同条目拼成一个不存在的切片。现在按同一条目匹配。
- RAN 重启命令失败原先未检查返回码；现在立即抛错，停止后续操作。
- 验证原先侧重宿主机配置；现在同时检查进程加载和 NRF 实际注册。
- 页面增加核心网配置列，按钮明确标为“新建切片（核心网 + RAN）”。清册的“配置就绪”与账本执行成功分开表达。
