# 架构与能力边界

网页 `intent-driven/ui/` 通过 HTTP 调用同目录 Python 服务。后端注册动作，完成参数规范化、预检、计划执行、回读和审计。规则解析独立可用；配置模型时可使用模型解析，失败回退规则。状态和日志由部署时创建，仓库不提供原机器的运行状态。

| 链路 | 实现与边界 |
| --- | --- |
| 新增 UE / 修改 QoS | 操作核心网订阅数据库并检查鉴权和切片支持；软件 UE 启动和真实手机接入是不同步骤 |
| 创建/激活切片 | 核心网与 RAN 支持需共同满足后端验收条件；只有核心网写入成功不能代表整个切片创建成功 |
| DU 下行 MCS 上限 | 意图 → 自定义控制 xApp → FlexRIC → E2 自定义 MAC SM → DU 调度策略；支持运行中设置、回读与回滚 |
| 切片下行 PRB 上限 | 同一控制链路，限制目标切片的新传输下行 PRB 预算；有请求关联、应用回执、统计和回滚 |
| KPM 监测 | FlexRIC 监测 xApp 获取 RAN 数据，供运行检查与观察使用 |
| NWDAF | AnLF/MTLF、SMF 事件订阅、Mongo 事件数据、S3 兼容对象存储及相关检测/预测组件 |

RAN 控制使用本项目定制 MAC 服务模型（SM ID 142），不是完整的标准 E2SM-RC 实现。PRB 上限不等同于独占保留、上下行全部隔离或承诺固定吞吐。MCS/PRB 控制成功需要检查 DU 回执/实际值，不能只使用 RIC ACK。

控制 xApp 为按请求执行的工具，与持续运行的 KPM/GTP-MAC 监测 xApp 分开。编译后的控制程序由后端调用；所有源文件在 `intent-driven/ran/`，DU 对应补丁在 `patches/oai.patch`、`patches/flexric.patch`，策略头文件同时作为 OAI 覆盖文件保存。

保留的运行恢复机制包括启动锁、UE 修复、核心网/NWDAF 看门狗、KPM/FlexRIC 检查和意图状态落盘恢复。它们是原实验床的具体实现，会调整运行服务；重新部署时须审阅与本机环境的匹配程度。

近期修复包括：新增 UE 动作统一为 `add_subscriber` 并补全模块注册；页面与后端动作对应；SD 大小写统一；服务开通缺省 SD 解析；主 UE 切换避免复用在线额外 UE 的 IMSI；QoS ARP 使用正确的嵌套字段。相关测试保存在仓库。

原机器存在一个仍在线但缺少 SM 订阅行的历史 UE；导出的新部署模板会生成完整的四套订阅，不复制该数据库缺失状态。迁移后应重新执行 UE 接入验收。
